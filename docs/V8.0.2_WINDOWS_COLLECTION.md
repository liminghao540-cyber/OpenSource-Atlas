# V8.0.2 — Read-only Windows Event Log collection

## Explicit opt-in

The `opensource_atlas.windows_events.collect_windows_events()` library
function reads a bounded number of recent events from one of three allow-listed
Windows logs: Application, System, or Security. The caller must invoke it
explicitly. It is not a background service or continuous monitor.

Example:

```python
from opensource_atlas.windows_events import collect_windows_events

result = collect_windows_events(log_name="System", hours=24, max_events=100)
for event in result["events"]:
    print(event)
```

The function uses the built-in Windows PowerShell executable with a constant
script. Request data is passed through standard input as JSON rather than
interpolated into command text. Collection is bounded to 1–168 hours,
1–500 events, and a caller-selected timeout of at most 120 seconds.

## Permissions and troubleshooting

Start with the System or Application log. Access to Security events may require
an elevated terminal or an account with the relevant Windows event-log rights.
The collector does not attempt privilege escalation.

## Safety boundaries

- Read-only: it does not clear, modify, export, or upload event logs.
- No scheduled task, service, persistence, or automatic startup is installed.
- No process termination, file deletion, network blocking, or account changes.
- Event content is untrusted input and must be reviewed before response planning.
- This is a bounded snapshot, not continuous real-time monitoring or EDR.
- Empty results do not prove the host is safe.
