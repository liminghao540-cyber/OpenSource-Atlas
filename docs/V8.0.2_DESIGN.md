# V8.0.2 — Asset Inventory and Finding Correlation

V8.0.2 adds deterministic, in-memory asset normalization and finding correlation.
All records are explicitly supplied by the caller. The release does not discover
endpoints, collect telemetry, persist inventory, connect to SIEM/EDR products,
or execute response actions.

## Asset inventory

Use build_asset_inventory(records) from opensource_atlas.assets. Identifiers
are trimmed and case-normalized; duplicates are reported as row errors.
Optional hostname, platform, environment, owner, and tags are bounded.

## Finding correlation

Use correlate_findings(findings, assets=..., suppressions=..., now=...) from
opensource_atlas.correlation. Equivalent findings are grouped by a stable
SHA-256 fingerprint over rule, asset, title, and evidence. Results retain
occurrence counts, time bounds, source provenance, maximum severity, and
maximum supplied confidence. Asset enrichment uses only the supplied inventory.

Suppressions match an exact fingerprint and are active only while a valid
expires_at timestamp is later than evaluation time. Suppression changes triage
state only; it does not delete evidence or prevent detection.

## Safety boundaries

- Caller-supplied data only; in-memory processing only.
- No automatic asset discovery, background monitoring, or telemetry collection.
- No persistence, remote connector, or external side effect.
- Confidence and severity are triage inputs, not calibrated probabilities.
- Missing asset matches or no finding do not prove a host is safe.
- Response planning remains dry-run only and execution_enabled remains false.
