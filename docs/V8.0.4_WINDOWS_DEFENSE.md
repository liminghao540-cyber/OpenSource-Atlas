# V8.0.4 — Windows Defense integration

## Scope

V8.0.4 brings the useful V6/V7 Windows Defense capabilities into the Python
package as explicit APIs. The collector and monitor are opt-in and run only
when called by the user in a foreground process.

## V6-style host telemetry

On Windows 10 / PowerShell 5.1, call:

    from opensource_atlas.windows_defense import collect_windows_host_snapshot, analyze_host_snapshot

    snapshot = collect_windows_host_snapshot(max_connections=500)
    findings = analyze_host_snapshot(snapshot)

The bounded snapshot includes established TCP connections, listening sockets,
process name/PID/path, Authenticode status, SHA-256 (skipped for files above
100 MiB), Windows Firewall profile state, and Defender Operational events
1116/1117. Collection is capped at 1,000 TCP rows per state and 100 Defender
events. Some fields can be unavailable without elevation; that is reported as
limited visibility, not proof of compromise.

The risk model is heuristic and explainable. It reuses V6-style signals:
script-capable system tools, user-writable paths, unsigned binaries,
signature/hash mismatch, high per-process connection fan-out, and selected
unusual remote ports. A disabled firewall profile is high severity; unavailable
firewall state is informational and is not misreported as disabled.

For bounded foreground monitoring:

    from opensource_atlas.windows_defense import iter_windows_defense_events

    for finding in iter_windows_defense_events(max_polls=60, max_runtime_seconds=300):
        print(finding)

The first sample establishes a baseline. Later samples yield newly observed
connections/listeners and new Defender/firewall findings. Defaults are 8
seconds, 60 polls, and 5 minutes. No service, scheduled task, startup entry,
persistent cursor, or remote upload is installed.

## V7-style temporary outbound block

Firewall response is a separate explicit API and is never called by the
collector, monitor, detector, or response planner.

    from opensource_atlas.firewall_response import create_temporary_outbound_block

    result = create_temporary_outbound_block("8.8.8.8", approval="BLOCK", ttl_minutes=10)
    print(result)

The call requires Windows, an elevated PowerShell context, a public global
unicast IP, and the exact approval token BLOCK. The rule blocks that IP for all
outbound traffic and may interrupt legitimate services. Default TTL is 10
minutes; allowed TTL is 1–60 minutes; maximum owned rules is 5. It does not
terminate a process, delete a file, change firewall profiles/default policies,
or alter Defender settings.

State is recorded in data/firewall-response-state.json and an append-only
data/firewall-response-ledger.jsonl. Expiry is enforced only when the caller
explicitly runs cleanup; it is not a background timer:

    from opensource_atlas.firewall_response import cleanup_expired_temporary_blocks
    print(cleanup_expired_temporary_blocks())

Rollback previews by default:

    from opensource_atlas.firewall_response import rollback_temporary_outbound_blocks
    print(rollback_temporary_outbound_blocks())          # preview only
    print(rollback_temporary_outbound_blocks(preview=False))  # execute exact cleanup

Before removal, the PowerShell script verifies the exact rule name, description
marker, display-name prefix, group, outbound direction, block action, and remote
address. If ownership does not match, it refuses removal. Keep the state and
ledger files for audit. A missing state file means the package cannot safely
identify rules it owns.

## Safety and limitations

- Default monitoring is read-only. There is no unattended or automatic block.
- Firewall response is not independent of Windows Firewall; it creates a
  Windows Firewall rule only after an explicit user call and approval token.
- A public IP may be shared by unrelated services. Review the destination
  before approving a block.
- Expiry cleanup is caller-triggered. Do not assume a rule disappears at its
  expiry time if cleanup is never run.
- CI mocks PowerShell. Live Windows 10 validation is still required.
- This is a learning/triage tool, not a certified EDR or a guarantee of
  prevention. Risk scores are not malware verdicts.
