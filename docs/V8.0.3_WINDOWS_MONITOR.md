# V8.0.3 — Bounded Windows Event Log Monitor

## Purpose

V8.0.3 adds an opt-in polling iterator for Windows Event Logs. It is designed
for a user-started foreground process, not as a Windows service or EDR agent.

## Quick start

Run from an activated project environment on Windows 10 or later:

```python
from opensource_atlas.windows_monitor import iter_windows_events

for event in iter_windows_events(
    log_name="System",
    poll_interval_seconds=5,
    max_polls=60,
    max_runtime_seconds=300,
):
    print(event)
```

Stop by ending iteration (for example, Ctrl+C in a foreground script), closing
the iterator, or passing a `threading.Event`-compatible `stop_event` and setting
it from another thread. The default run ends after 60 polls or five minutes.

## Behavior

- Reads only the allow-listed Application, System, or Security log.
- By default, captures the newest record ID once, then yields only later records.
- Keeps the record-ID cursor in memory; it is not persisted between runs.
- Poll interval is bounded to 5–300 seconds; each poll returns at most 100 events.
- A run is bounded to 10,000 polls and 3,600 seconds maximum.
- Uses a constant PowerShell script and passes request values as JSON on stdin.
- Yields normalized event dictionaries that can be passed to the existing
  detection and correlation APIs.

## Safety and limitations

- Read-only: no event log is cleared, changed, or exported to a remote service.
- No service, scheduled task, startup entry, background daemon, or persistence
  is installed.
- No process termination, file deletion, quarantine, firewall change, or
  account modification is performed.
- No network request or telemetry upload is performed.
- Security log access may require administrator privileges; no elevation is
  attempted. Start with System or Application.
- Event messages are untrusted data. A missing event, empty result, or
  no-rule-matched assessment does not prove the host is safe.
- Record IDs can reset if a log is cleared or recreated; this version does not
  persist or reconcile cursors across such resets.
- Automated tests mock PowerShell. A successful CI run does not replace a
  live Windows 10 validation on the target computer.
