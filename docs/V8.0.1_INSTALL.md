# OpenSource Atlas V8.0.1 — Installation and Verification

> **Status:** Release candidate preparation. This guide describes the source currently being prepared; it is not evidence that a public release artifact has been published.

## Requirements

- Python 3.11 or newer
- Git (for installing from the repository)
- Internet access only for the existing public GitHub repository inspection feature

The V8 event parsing, detection, and response-planning modules have no third-party runtime dependencies.

## Install from a source checkout

Clone the repository and check out the release-preparation branch while it is under review:

```bash
git clone https://github.com/liminghao540-cyber/OpenSource-Atlas.git
cd OpenSource-Atlas
git checkout v8.0.1-release-prep
python -m venv .venv
```

Activate the environment:

Windows PowerShell:
```powershell
.\.venv\Scripts\Activate.ps1
```

macOS/Linux:
```bash
source .venv/bin/activate
```

Install and verify:

```bash
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python -m pytest
python -c "from opensource_atlas import __version__; print(__version__)"
```

Expected package version for this candidate: `8.0.1`.

## Existing CLI and dashboard

Inspect a public repository:

```bash
atlas inspect pallets/flask
atlas inspect pallets/flask --format json --output report.json
```

Start the local dashboard:

```bash
atlas-web
```

Open http://127.0.0.1:8765. Stop with Ctrl+C. The dashboard is local-only and is not reviewed for internet-facing deployment.

## Try the V8 event pipeline

```python
from opensource_atlas.events import ingest_jsonl
from opensource_atlas.detection import analyze_event
from opensource_atlas.response import build_response_plan

sample = '{"event_type":"malware_detected","source":"demo","asset":"host-01"}'
result = ingest_jsonl(sample)

for event in result["events"]:
    finding = analyze_event(event)
    plan = build_response_plan(finding)
    print(finding)
    print(plan)
```

The parser accepts text supplied by your application. It does not read files, receive network traffic, or connect to external products. The detector analyzes only the normalized event passed to it. The response planner produces a proposal; it never executes an action and keeps `execution_enabled=false`.

## Safety boundaries

- Do not feed secrets, credentials, or sensitive personal data into sample events.
- Treat findings as triage signals, not confirmed incident verdicts.
- Validate and authenticate event sources in the application that supplies the events.
- Do not expose the local dashboard to untrusted networks.
- No endpoint monitoring, network scanning, SIEM integration, or autonomous response is included.
- Production use requires a separate threat model, access control, secure secret handling, audit design, and security review.
